# mapdb-golang-store — MapDB5 store engine for Go

A Go port of the MapDB5 storage engine: persistent, transactional
collections (B-link trees, Bε-trees, hash trees, queues, atomics) on top of
a record store with an in-memory, file and write-ahead-log backend.
Module path: `github.com/mapdb/mapdb5-go`.

The Java implementation ([mapdb-java-store](https://github.com/mapdb/mapdb-java-store))
is the reference. Persisted records, headers and frames follow its byte
layouts. The serializers, stores, BTree, BufferedPageFormat, hashers,
queues and DB catalog are golden-tested against bytes produced by the Java
classes; the HTree, IndexTree and SortedTableMap layouts were checked
against the Java sources but have no Java-generated byte vectors yet.
The MapDB5 file format itself is **not frozen yet**, so there is no
cross-version or cross-language compatibility guarantee.

## Requirements

- Go 1.24+.
- The collection interfaces come from
  [mapdb-golang](https://github.com/mapdb/mapdb-golang). During development
  `go.mod` resolves it with a `replace` directive to a sibling checkout, so
  clone both side by side:

  ```sh
  git clone https://github.com/mapdb/mapdb-golang
  git clone https://github.com/mapdb/mapdb-golang-store
  cd mapdb-golang-store && go test ./...
  ```

## Quick start

```go
d, err := db.FileDB("data.db").TransactionEnable().Make()
if err != nil {
	panic(err)
}
defer d.Close()

users, err := db.TreeMap[int64, string](d, "users", ser.LongFormat, ser.StringGroupFormat).CreateOrOpen()
if err != nil {
	panic(err)
}
users.Put(1, "alice")
d.Commit()

name, ok := users.Get(1) // "alice", true
```

The runnable version is `db/example_test.go`. Operations panic with
`*mapdb5.DBError` (constructors and `Close` return `error`); see `errors.go`
for the error kinds.

## Packages

| Package | Contents |
|---------|----------|
| `db` | `DB` facade, `DBMaker` backends, named-object catalog, typed makers |
| `store` | `Store`/`StoreDelta`/`StoreTx`; OnHeap, ByteArray, Direct, WAL, AppendOnly, read-only wrappers |
| `btree` | `BTreeMap` (B-link tree), `BufferTreeMap` (Bε-tree), `TreePump` bulk build |
| `htree` | `HTreeMap`, `HTreeMap48`, `HTreeMapExternal`, `HTreeCache`, DirTree, `HTreePump` |
| `indextree` | `IndexTreeLongLongMap`, `IndexTreeList` |
| `sortedtable` | immutable bulk-loaded `SortedTableMap` |
| `queue` | `QueueLong`, `PersistentBlockingQueue` |
| `ser`, `format`, `bin`, `mdhash` | serializers and group formats, buffered page format, binary I/O, hashers |

## What is implemented

- **M0 (done):** `bin` package — `Writer`/`Reader`, big-endian scalars, mapdb
  packed varints (7 bits/byte, MSB-first, `0x80` terminator), writer pooling;
  root `DBError` hierarchy; `store` parity checksums (p1/p4/p16). Golden
  vectors + race tests.
- **M1 (done):** `ser` package — `Serializer[A]`/`AnySerializer` (erased
  store boundary), built-in scalar/array/string/big-number/compression
  serializers, `GroupFormat[K]` family (fixed-stride, delta, blob+offsets,
  front-coded prefix, object-array, tuple, columnar), `Value` sum type,
  UTF-16 string order.
- **M2 (done):** `store` package — `Store`/`StoreDelta`/`StoreTx` interfaces,
  erased-boundary validation, `StoreOnHeap`, `StoreByteArray`,
  `ReadOnlyWrapper`, lease table, generic store TCK + delta TCK.
- **M3 (done):** `StoreDirect` — 1 MiB paged volume (heap + file), parity
  index values, free-list long stacks, linked oversize records, verify,
  compact, `wal*` replay hooks for the WAL's inner store.
- **M4 (done):** `StoreWAL` — v3 segment-set WAL (`MDBS.WAL`,
  `<base>.wal.<16 hex>`), OFD store lock (`<base>.lock`), two-pass recovery
  with clean-mark adjudication + torn-tail handling, two-pass section writer
  with domain-bound CRCs, incremental cleaner + checkpoint, delete-on-close,
  `walIO` fault-injection seam. Full store TCK incl. delta.
- **M5 (done):** `btree` package — persistent B-link tree (`BTreeMap`):
  Java-compatible node wire format (packed header, key group, child recids /
  value group + fence), per-recid sharded lock table with reentrancy
  tripwire, Lehman-Yao splits (right sibling first, dual root-grow gate),
  O(1) size counter, external-value mode with reclamation read barrier,
  tx-aware left-edge refresh + poison, weakly consistent ascending and
  descending bounded iterators, full navigable surface (floor/ceiling/
  lower/higher, head/tail/sub, rank/select, poll first/last), `TreePump`
  bulk builder (`CreateFromSorted`, `pump.ErrNotSorted`), structural
  `Verify`, open lease on the root pointer. Satisfies the sibling
  collections `MutableMap` interface.
- **spec2/W3 (done):** `queue` package — `QueueLong` (persistent FIFO of
  `(timestamp,value)` u64 pairs, three-recid reopenable, O(1) remove/bump,
  takeUntil/forEach with re-entry tripwire, byte-compatible node +
  pointer records) and `PersistentBlockingQueue` (`PBQ[V]` — FIFO/LIFO/
  circular modes, header + node records byte-compatible, blocking
  `Take`/`Put` plus timed variants via a channel-backed condition
  variable, close-handle wakeup, verify/purge).
- **spec2/W2 (done):** `BTreeMap` modification listeners — sync + deferred
  `MapModificationListener` lists, copy-on-write registration, panic-safe
  delivery, split/counter/listener failure precedence, external-barrier
  re-entry tripwire, per-listener value isolation, value-comparability
  identity domain.
- **spec2/W4 (done):** `db` package — `DB` facade with the Java `MDBC` v1
  name catalog, `DBMaker` backend builder (heap/bytearray/direct/file/WAL,
  read-only, recovery limits, delete-on-close), typed makers (TreeMap,
  TreeSet, atomics Var/Long/Integer/Boolean/String, blocking queues;
  `QueueLong` is used directly from package `queue`), navigable set views with orientation-aware bounds, `Bind`
  secondary views (indexes, histogram, inverse, filtered maps, key/value
  projections), serializer-descriptor catalog checks, same-live-instance
  cache.
- **M6a (done):** `StoreAppendOnly` — in-memory append-only StoreDelta
  (16-aligned extents in 1 MiB pages, lock-free atomic readers, serialized
  writers, slice-retiring compaction); `db.MemoryAppendOnlyDB()`.
- **M7 (done):** `mdhash` (Java-compatible seeded hashers), `htree` —
  DirTree, `HTreeMap` / `HTreeMap48` / `HTreeMapExternal`, `HTreePump`,
  `HTreeCache` (TTL / max-size / store-size eviction, Java ExpireQueue
  layout, overflow tier, eviction listener); `indextree`
  (`IndexTreeLongLongMap`, `IndexTreeList`); `sortedtable`
  (`SortedTableMap`).
- **M6b (done):** `format` package — `BufferedPageFormat` (R1 page
  convention, reverse-readable op frames, base fingerprints) and
  `btree.BufferTreeMap` (Bε-tree over `StoreDelta`, blind writes into node
  buffers, one-level flush, leaf consolidation); `db` maker. Golden bytes
  generated by the Java classes.

- **M8 (done):** background maintenance (`MaintenanceExecutor`; StoreWAL
  cleaner and StoreDirect compaction tasks via `StartMaintenance` /
  `AttachMaintenance`, off by default), StoreDirect incremental compaction
  (`CompactStep` / `CompactIncremental`), and benchmarks: `testing.B` in
  `bench/` and the standalone runner `go run ./cmd/bench -mode full`, with
  the same workloads as the Java JMH suite.

**Performance.** Reads take locks (no optimistic reads, see
PORTING-GAPS). On a 32-core machine with 1M Long keys, BTreeMap point
reads over StoreDirect reach about 1 M ops/s on one goroutine and 8.5 M
ops/s on 32. That is on par with the Java implementation's locked-read
numbers for concurrent readers, and about half for a single reader.
Writes are currently several times slower than Java's. Deliberate
deviations from the Java reference are listed in [PORTING-GAPS.md](PORTING-GAPS.md).

Other ports of the same engine: [mapdb-rust-store](https://github.com/mapdb/mapdb-rust-store),
[mapdb-zig-store](https://github.com/mapdb/mapdb-zig-store).
